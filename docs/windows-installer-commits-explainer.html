先读 README 里的安装命令

这是用户最先接触到的 PowerShell。我们先把这一行拆开。

README.md普通安装命令
irm https://raw.githubusercontent.com/winter-loo/sing-box-tui/main/scripts/windows/install.ps1 | iex

irm

是 Invoke-RestMethod 的短名。意思是：从 URL 请求内容。这里请求到的是 install.ps1 脚本文本。

|

管道。把左边命令的输出，交给右边命令。像 Python 里把一个函数结果传给下一个函数。

iex

是 Invoke-Expression 的短名。意思是：把传进来的文本当作 PowerShell 代码执行。

安全直觉：irm URL | iex 等于“下载远程脚本并执行”。只应该对你信任的仓库这么做。

如果 raw GitHub 被挡，README 现在还给了代理版：

README.md代理安装命令
irm https://deeloo.cn/anywhere/https://raw.githubusercontent.com/winter-loo/sing-box-tui/main/scripts/windows/install.ps1 | iex

PowerShell 基础语法：对照 Python 理解

下面只讲这个脚本里用到的语法，不讲全部 PowerShell。

变量：$Name

PowerShell 变量一定带 $。Python 写 name = "abc"，PowerShell 写 $name = "abc"。

类型标注：[string]$Url

类似 Python 的 url: str。脚本里常见 [string]、[int]、[switch]。

函数：function Name {}

类似 Python def name(...):。PowerShell 用大括号，不靠缩进定义代码块。

if：if (...) {}

条件必须放括号，代码块放大括号。-not 是“不是”，类似 Python not。

错误处理：try/catch

几乎就是 Python try/except。这个脚本大量用它实现“失败就换方案”。

过滤：Where-Object {}

类似 Python list comprehension 的 if 部分，用来筛选 GitHub release assets。

脚本开头的参数块

scripts/windows/install.ps1param block
[CmdletBinding()]
param(
    [string]$Repo = "winter-loo/sing-box-tui",
    [string]$Version = "latest",
    [string]$InstallDir = "$env:LOCALAPPDATA\sing-box-tui",
    [string]$GitHubProxy = "https://deeloo.cn/anywhere",
    [ValidateRange(1, 16)]
    [int]$DownloadParts = 4,
    [switch]$Force
)
Python 类比：这像一个函数签名 + argparse 默认值。比如 $DownloadParts = 4 就是默认开 4 个下载分片。

你问到的几种“方括号语法”

PowerShell 里 [...] 经常表示“类型”或“参数规则”。这和 Python 不太一样，所以单独拆开看。

[ValidateRange(1, 16)]

这是参数验证规则，意思是：用户传进来的值必须在 1 到 16 之间。像 Python argparse 里手写 if not 1 <= value <= 16: raise。

[int]$DownloadParts = 4

[int] 是类型声明，也是转换提示。这个参数应该是整数；如果用户传 "4"，PowerShell 会尝试转换成整数 4。

[int64]$length

int64 是 64-bit 整数，适合文件大小这种可能很大的数字。普通 [int] 通常是 32-bit，最大大约 2GB。

[double]$length

double 是浮点数。算百分比或除法时用它，避免整数除法/精度问题。

为什么这里要写 [int]？类型转换 / cast
$actualParts = [Math]::Min($Parts, [int]$length)

这里的 [int]$length 是一个 cast：把 $length 转成 int 后再传给 [Math]::Min。原因是 $Parts 是 [int]，而 $length 原本是 [int64]。显式转换后，Min 更容易选择正确的重载，也表达了这里的意图：part 数量不可能超过文件 byte 数量。

小心：这种 cast 在这里安全，是因为 $Parts 最多 16，而且这个表达式只是为了限制“分片数量”。真正保存文件大小和 byte offset 的变量仍然用 [int64]，避免大文件溢出。

PowerShell 调用 .NET 的语法

这个脚本不只用 PowerShell cmdlet，还直接调用 .NET 类。看到 [Something]::Member 时，可以把它当成 Python 的“类名.静态方法/静态属性”。

.NET static member启用 TLS 1.2
[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor [Net.SecurityProtocolType]::Tls12
[Net.ServicePointManager]
这是 .NET 里的一个类，负责一些老式网络请求的全局设置。
::SecurityProtocol
:: 表示访问类上的静态属性，不需要先创建对象。
[Net.SecurityProtocolType]::Tls12
这是一个枚举值，表示 TLS 1.2 协议。
-bor
bitwise OR。这里的意思是：保留已有协议设置，同时把 TLS 1.2 也加入进去。
Python 类比：有点像 ServicePointManager.SecurityProtocol |= SecurityProtocolType.Tls12。它不是业务逻辑，而是网络兼容性设置：确保下载 HTTPS 资源时可以使用 TLS 1.2。

脚本里更多常见语言块

$request.Method = "GET"

设置对象属性。类似 Python request.method = "GET"。

$request.GetResponse()

调用对象方法。类似 Python request.get_response()。

[System.Net.HttpWebRequest]::Create($Url)

调用 .NET 类的静态方法创建 request 对象。类似 Python HttpWebRequest.create(url)。

New-Object byte[] 1048576

创建 1MB byte buffer。类似 Python bytearray(1048576)，用于一块一块读下载流。

@()

数组字面量。$partFiles = @() 类似 Python part_files = []。

@{ ... }

hashtable，类似 Python dict。HTTP headers 就用这种写法。

[pscustomobject]@{ ... }

创建一个带字段的小对象，像 Python dict/dataclass。每个下载分片都用它保存 Index、Path、Start、End、Job、Attempts。

$partFiles += $part

把元素追加到数组。类似 Python part_files.append(part)，但 PowerShell 这里写成 +=。

$_

当前管道对象。Where-Object { -not $_.Completed } 里的 $_ 就是正在被检查的那个 part。

$($part.Index + 1)

字符串插值里的子表达式。简单变量可写 $name，复杂表达式要包进 $(...)。

-ErrorAction SilentlyContinue

这次命令失败也不要打印红色错误。常用于“尝试删除临时文件，不存在也没关系”。

try { } finally { }

finally 不管成功失败都会执行。这里用来关闭 response、stream、job，类似 Python 的 finally 或 with 清理资源。

展开：几个 PowerShell 运算符怎么读
  • -eq：equals，等于。Python 是 ==。
  • -ne：not equal，不等于。Python 是 !=。
  • -gt：greater than，大于。Python 是 >。
  • -le：less or equal，小于等于。Python 是 <=。
  • -match：正则匹配。类似 Python re.search(...)。
  • -and / -or / -not：逻辑与/或/非。
  • -bor：bitwise OR，按位或。这里用于给已有网络协议设置追加 TLS 1.2。
  • -ErrorAction SilentlyContinue：这个命令出错时安静跳过。常用于清理临时文件。

重点逻辑 1：GitHub 代理 fallback

这是 commit f7493521 的核心。它让脚本在网络不好时更稳。

概念版代码先直连，失败再代理
function Invoke-GitHubApi([string]$Url) {
    try {
        return Invoke-RestMethod -Uri $Url
    } catch {
        if ([string]::IsNullOrWhiteSpace($GitHubProxy)) {
            throw
        }
        return Invoke-RestMethod -Uri (Join-GitHubProxyUrl $Url)
    }
}
收到一个 GitHub URL。
比如 release API：https://api.github.com/repos/.../releases/latest。
先直接请求。
如果成功，函数立刻 return，后面的 proxy 不会用到。
如果失败，进入 catch。
这就像 Python 进了 except。
检查是否允许使用 proxy。
如果 $GitHubProxy 是空字符串，就 throw，把错误继续抛出去。
拼接代理 URL 再请求。
Join-GitHubProxyUrl 会把 proxy + "/" + originalUrl 拼起来。
12 岁版：你去 GitHub 商店买东西，正门打不开。脚本说：“那我走代购通道再试一次。”如果连代购地址都没有，就只能报错。

脚本实际做的事

问服务器文件大小。
用 HTTP HEAD 请求得到 ContentLength，保存为 [int64]，因为文件大小可能很大。
确认支持范围下载。
看服务器是否支持 byte ranges。支持才可以“从第 X 个 byte 下载到第 Y 个 byte”。
计算每块范围。
[Math]::Min、[Math]::Ceiling 是 .NET 数学函数；[int]、[int64]、[double] 用来明确数值类型。比如文件 100MB、4 块：大约 0-25MB、25-50MB、50-75MB、75-100MB。
每块开一个 job。
Start-Job 像开后台 worker。每个 worker 只下载自己的 byte range。
主循环监控进度。
如果某块文件大小一直不变，说明可能卡住。
只重试卡住的块。
最多试 3 次；不用重下已经成功的块。
检查大小并合并。
每块大小对了，按顺序写入最终文件。

关键代码片段怎么读

概念版代码每个 job 下载一个范围
$request.AddRange($Start, $End)
$response = $request.GetResponse()
while (($read = $inputStream.Read($buffer, 0, $buffer.Length)) -gt 0) {
    $outputStream.Write($buffer, 0, $read)
}
Python 类比：AddRange(start, end) 像给 HTTP 请求加 header：Range: bytes=start-end。然后循环读网络 stream，写入临时文件。

完整程序逻辑流程

把上面的知识合起来，看当前 scripts/windows/install.ps1 的主流程。

读取参数。
默认仓库、版本、安装目录、sing-box core 版本、代理地址、下载分片数、超时时间等。
设置错误策略。
$ErrorActionPreference = "Stop"：让错误更像 Python exception，方便 try/catch 捕获。
准备 helper functions。
定义打印步骤、拼代理 URL、请求 GitHub API、单线程下载、并行下载、GitHub asset 下载、找 release asset、改 PATH 等函数。
检查 sing-box core。
如果用户没传 -SkipSingBox，并且系统里没有 sing-box，就下载并安装 core。
创建安装目录。
类似 Python os.makedirs(install_dir, exist_ok=True)。
检查 sing-box-tui.exe 是否已存在。
存在且没有 -Force 就不重复安装。
获取最新 release asset。
调用 GitHub release API，筛选名字包含 Windows x64 且后缀是 .zip 的资产。
下载 zip。
优先并行下载。失败则 fallback 到单请求。直连 GitHub 失败则 fallback 到 proxy。
解压并复制 exe。
Expand-Archive 解压；找到 sing-box-tui.exe；复制到安装目录。
清理和收尾。
删除临时 zip / 解压目录，把安装目录加入用户 PATH，最后打印如何运行。
一句话：这个 installer 的主线是“找版本 → 下载依赖 → 下载 app → 解压复制 → 加 PATH”，网络相关的困难都被包在“直连/代理 fallback”和“并行下载/重试”里。
