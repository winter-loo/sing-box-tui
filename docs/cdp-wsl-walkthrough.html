The Problem It Solves

The provider scripts talk to Chrome through Chrome DevTools Protocol endpoints such as http://127.0.0.1:9229/json/list and ws://127.0.0.1:9229/devtools/page/.... That works when Chrome and Python run in the same network namespace.

In WSL2, Python runs inside Linux while Chrome may run on Windows. Windows 127.0.0.1 is not the same as WSL 127.0.0.1. Chrome also commonly reports debugger WebSocket URLs with loopback hosts, even when WSL needs to connect through the Windows-side WSL gateway.

Key idea: keep the provider scripts simple. They ask this helper for an effective CDP URL, then use that same effective URL to fix any loopback WebSocket URL returned by Chrome.

Guided Tour Through The Workflow

This is the actual runtime path when you run a command such as python3 scripts/get-airtcp-singbox-url.py --cdp-windows-relay.

1

The command enters a provider script

Start at scripts/get-airtcp-singbox-url.py. parse_args() defines the transport flags: --cdp-url, --cdp-windows, --windows-host, and --cdp-windows-relay. 

python3 scripts/get-airtcp-singbox-url.py --cdp-windows-relay
2

main() decides whether relay mode is active

The provider script sets relay from the CLI flag or WSL_CDP_WINDOWS_RELAY=1. That variable decides whether cdp_wsl.py only rewrites hosts or also starts a Windows-side TCP relay. 

relay = args.cdp_windows_relay or os.environ.get(WINDOWS_RELAY_ENV) == "1"
3

The provider script enters wsl_windows_cdp_url()

This is the handoff from provider code to transport code. The context manager yields an effective CDP URL and guarantees relay cleanup later. 

with wsl_windows_cdp_url(
    args.cdp_url,
    enabled=args.cdp_windows,
    windows_host=args.windows_host,
    relay=relay,
) as cdp_url:
4

cdp_wsl.py resolves the reachable Windows host

resolve_wsl_windows_cdp_url() rewrites http://127.0.0.1:9229 only when Windows mode or relay mode is enabled. It asks find_windows_host() for the host, preferring WSL_WINDOWS_HOST, then the WSL default gateway, then /etc/resolv.conf. 

http://127.0.0.1:9229
http://172.28.192.1:9229
5

Relay mode starts a temporary PowerShell bridge

If Chrome is only listening on Windows loopback, start_windows_cdp_relay() launches PowerShell. The relay listens on the WSL-visible host and forwards raw TCP bytes to Windows 127.0.0.1:<port>. 

WSL -> 172.28.192.1:9229 -> PowerShell relay -> 127.0.0.1:9229 -> Chrome
6

The provider script calls Chrome's HTTP CDP API

Back in the provider script, list_targets(cdp_url) calls cdp_http_json(cdp_url, "/json/list"). The HTTP opener uses ProxyHandler({}) so proxy environment variables do not hijack local CDP traffic. 

targets = list_targets(cdp_url)
7

The provider script chooses or opens the right browser tab

The AirTCP path calls find_airtcp_target(). If no matching page target exists, open_user_target() asks Chrome to create a new tab through /json/new. BaiPiao and Baobeiyun use the same pattern with provider-specific target matching.

8

The WebSocket URL is made reachable from WSL

Chrome's target contains webSocketDebuggerUrl. If Chrome reports ws://127.0.0.1:..., rewrite_loopback_websocket_url() replaces that host with the same effective CDP host used for HTTP.

9

CdpConnection opens the raw CDP WebSocket

The provider script's CdpConnection.connect() manually performs the WebSocket handshake, then CdpConnection.call() sends CDP JSON messages such as Page.enable, Runtime.enable, and Runtime.evaluate.

10

Provider-specific extraction runs inside the tab

AirTCP calls capture_subscription_url(), which uses evaluate() to inspect page JavaScript and DOM text. If needed, it clicks the Sing-box import button and watches CDP navigation events for a sing-box://... URL.

11

The result is decoded and printed

The provider script returns either the direct HTTPS subscription URL or the sing-box:// import URL depending on flags. It writes to stdout or to --output.

12

Context cleanup closes the relay

When the with block exits, control returns to wsl_windows_cdp_url(). Its finally block calls stop_windows_cdp_relay(), so relay cleanup happens even if extraction fails.

How to follow this live: run with WSL_CDP_LOG=1. The log lines correspond to steps 3, 4, 5, 8, and 12.

Big Picture Flow

The provider scripts call wsl_windows_cdp_url(...) around their CDP work. The context manager optionally starts a relay, yields a reachable URL, then cleans up the relay afterward.

1. Input A script starts with a URL such as http://127.0.0.1:9229.
2. Resolve If Windows mode is enabled, loopback is replaced with the Windows host visible from WSL.
3. Relay If relay mode is enabled, PowerShell listens on the WSL-visible host and forwards bytes to Windows 127.0.0.1.
4. Cleanup The yielded URL is used for CDP. When the context exits, the relay process is terminated. 
with wsl_windows_cdp_url(
    "http://127.0.0.1:9229",
    enabled=args.cdp_windows,
    windows_host=args.windows_host,
    relay=args.cdp_windows_relay,
) as cdp_url:
    targets = list_targets(cdp_url)

Public API

These are the functions and constants intended for the provider scripts to import.

wsl_windows_cdp_url

Main entry point. It resolves the effective CDP URL and optionally starts a temporary relay. It is a context manager so cleanup is tied to the lifetime of the provider script operation.

resolve_wsl_windows_cdp_url

Converts loopback URLs into Windows-host URLs when Windows mode is enabled. Non-loopback URLs are already explicit, so they are returned unchanged.

rewrite_loopback_websocket_url

Fixes Chrome's returned ws://127.0.0.1:port/... debugger URLs by replacing the host with the already chosen CDP host.

Environment constants

SING_BOX_TUI_CDP_URL, WSL_WINDOWS_HOST, and WSL_CDP_WINDOWS_RELAY are shared names used by the provider scripts and help text.

Constant Meaning
CDP_URL_ENV Environment variable that can override the default CDP URL.
WINDOWS_HOST_ENV Environment variable for explicitly setting the Windows host visible from WSL.
WINDOWS_RELAY_ENV Environment variable that enables relay mode when set by the caller.
CDP_LOG_ENV Environment variable that enables helper diagnostics when set to 1, true, yes, or on.
LOOPBACK_HOSTS Hostnames treated as local-only: 127.0.0.1, localhost, and ::1.

Host Resolution

find_windows_host() chooses the Windows-side address in a deliberate order.

  1. Use WSL_WINDOWS_HOST if the user supplied it. This is the escape hatch for unusual network setups.
  2. Use the default gateway from ip route show default. In WSL2, this is usually the Windows virtual network interface.
  3. Fall back to the first nameserver in /etc/resolv.conf. This is a secondary fallback because it can point at a resolver that is not useful for CDP. 
def find_windows_host() -> str | None:
    host = os.environ.get(WINDOWS_HOST_ENV)
    if host:
        return host

    host = _default_gateway()
    if host:
        return host

    host = _nameserver_from_resolv_conf()
    if host:
        return host

    return None
Why gateway first? During testing, the resolver IP accepted TCP but did not behave like a reachable Windows Chrome CDP endpoint. The WSL default gateway was the correct Windows-side interface for the relay.

The Relay Path

Chrome may ignore attempts to bind CDP to a non-loopback address and still listen only on Windows 127.0.0.1. In that case, WSL cannot connect directly. Relay mode starts a small PowerShell process on Windows:

  • It listens on the Windows host address that WSL can reach.
  • It connects onward to Windows 127.0.0.1:<cdp-port>.
  • It copies bytes both directions until either side closes.
process = subprocess.Popen(
    [powershell, "-NoProfile", "-Command", script],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    text=True,
)

The context manager stores that process and always calls stop_windows_cdp_relay() in the finally block. Normal exits and exceptions both take the cleanup path.

Security note: a reachable CDP endpoint can control the browser profile attached to it. Use a temporary Chrome profile and close it after extracting the subscription URL.

URL Rewrites

Two related rewrites happen in this file.

HTTP CDP URL rewrite

resolve_wsl_windows_cdp_url() rewrites only loopback hosts, and only when Windows mode or relay mode is enabled. 

http://127.0.0.1:9229
http://172.28.192.1:9229

WebSocket debugger URL rewrite

Chrome's /json/list response may contain a WebSocket URL with a loopback host. rewrite_loopback_websocket_url() reuses the effective CDP host so the HTTP and WebSocket connections go to the same reachable endpoint. 

ws://127.0.0.1:9229/devtools/page/abc
ws://172.28.192.1:9229/devtools/page/abc

replace_url_host() does the shared mechanical work. It parses the URL, preserves the original port, formats IPv6 hosts with brackets, and rebuilds the URL with urlunparse().

Failure Cases To Know

Failure Where it is handled What to do
No Windows host can be found. resolve_wsl_windows_cdp_url() Pass --windows-host or set WSL_WINDOWS_HOST.
Relay requested for a loopback-only effective URL. start_windows_cdp_relay() Use a non-loopback Windows host. The helper normally resolves one automatically.
Port cannot be inferred. _default_port() and relay validation Use an explicit URL such as http://127.0.0.1:9229.
PowerShell is unavailable. _powershell_path() Run from WSL on Windows, or avoid relay mode and provide a reachable CDP URL.
The relay process exits immediately. start_windows_cdp_relay() Check whether the port is already in use or Windows firewall is blocking the listener.

How The Provider Scripts Use It

The provider scripts expose this helper through command-line flags:

--cdp-windows --cdp-windows-relay --windows-host --list-pages-only 
python3 scripts/get-airtcp-singbox-url.py --cdp-windows-relay --list-pages-only
python3 scripts/get-baipiao-singbox-url.py --cdp-windows-relay
python3 scripts/get-baobeiyun-singbox-url.py --cdp-windows-relay

The first command is a low-risk smoke test. It only asks Chrome for page targets and exits before attempting provider-specific extraction. Once that lists a page, the WebSocket path should use the same reachable host.

For helper diagnostics, prefix a command with WSL_CDP_LOG=1. The logs show host resolution, URL rewrites, PowerShell relay startup, and relay cleanup without changing the extracted URL output format.
