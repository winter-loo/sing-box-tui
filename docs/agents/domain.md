# Domain docs

This is a single-context repository.

Before designing or implementing a change:

1. Read the root `CONTEXT.md`.
2. Read relevant decisions under `docs/adr/`.
3. Use the glossary's canonical terminology.
4. Surface conflicts with an existing ADR instead of silently overriding it.

Missing domain documentation is not itself an error; create it lazily when new terminology or a hard-to-reverse decision is resolved.
